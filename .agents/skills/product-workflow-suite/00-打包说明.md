### 外挂源码版本（2026-10-10 起）

版本以各 `SKILL.md` 的 `metadata.version` 为准，分组以 `metadata.suite-id` 为准。同包 Skill 同号；后续不跟主套件自动升号。`build-wiki-artifacts.mjs`、`build-unit-test-artifacts.mjs`、`build-git-hook-artifact.mjs`、`build-addon-artifacts.mjs` 已按此写入制品 `VERSION` 和返回的 `version`。可选 `version` 只用于校验请求，与 metadata 不一致时失败且不写制品。公共本地入口是：

```bash
node scripts/publish-public-skill.mjs --suite unit-test|wiki|git-hook|stitch --version <metadata.version> --out <目录>/<suite>-skills-<version>.zip [--source <dir>] [--commit <sha>]
```

它复用上面四个构建器，在输出父目录的隐藏独占临时目录生成完整 ZIP 和同名 `.sha256`，再同卷硬链接发布。不能硬链接时失败并保留已有目标，不跨卷复制。缺参数、重复参数、未知参数、非法或不一致版本先失败。目标父目录不存在会创建；已有 ZIP 或校验文件不覆盖、不删除。ZIP 已发布而校验失败时保留该 ZIP 并报告 partial 输出；清理只删私有 staging。输出打印实际路径、版本和 SHA-256。仓库源默认冻结完整 `HEAD`，`--commit` 只能指定仓库内已有提交，制品记录完整来源 SHA，不收录未提交或 ignored 内容。非仓库 `--source` 标成 `temporary-source` 且不写 SHA。这不是门户归一化包：`package_kind` 为 `local_install_bundle`，不含未确认的 `recommended_clients`，也不调用私仓 `publish_suite.py`，不能据此声称上传通过。

| 独立套件 | 基础号 | 当前源码号 |
|---|---|---|
| unit-test、git-hook、stitch、security-scan | 0.8.1 | 0.8.1 |
| wiki（统一后） | 原两外挂0.8.1历史基线 | 0.9.1来源marker保留；集成版本待主线确定 |

历史code-wiki、repo-wiki 的源码已在 0.8.1 基线之后改变，不能继续标成未变的 0.8.1。源码版本按用户指定为 `0.9.1`，不使用 dev 后缀。发布状态单独记录；旧制品内容和兼容性仍待核对。继承证据、语义化递增和验证见 [外挂版本决策](docs/adr/2026-10-10-addon-versioning.md)。

## 提交快照（不是正式发布）

现行标识是 `product-workflow`。根 `VERSION` 首行是 `product-workflow-0.9.3`，快照仍标 `snapshot-test`，不是正式 0.9.3，也不打 tag。完整门禁（单元、覆盖、评测、Python 双栈）仍未由本命令代替。快照只冻结一个已有提交，供安装识别和完整性复核：

```bash
node scripts/pack-release.mjs --snapshot --commit <完整或可解析 SHA，默认 HEAD> --version product-workflow-x.y.z --out <目录>/product-workflow-v0.9.3-snapshot-test-<SHA前12位>.zip
```

`--version` 必须与该提交里的 `VERSION` 首行一致，现行格式是 `product-workflow-x.y.z`。命令用 `git archive` 取该提交，不读工作区脏文件或 ignored 文件，也不要求 tag。包内 `VERSION` 追加 `snapshot: snapshot-test` 和 `source: <完整 SHA>`，`RELEASE.json` 记录同样两字段并纳入 `SHA256SUMS.txt`。输出名必须带对应 semver（允许 `v` 前缀）、完整 token `snapshot-test` 和 SHA 前 12 位，示例 `product-workflow-v0.9.3-snapshot-test-<sha12>.zip`；不必是唯一名。已有同名输出不覆盖、不删除；旁边的未知文件保留。临时目录只建在输出的父目录，发布只用同卷硬链接。新 `--tag` 只接受 `product-workflow-x.y.z`，不写 snapshot 字段。旧 `haitian-pw` 无 snapshot 包继续按原 `verify` 和 `migrate_suite` 识别，不改旧 tag 或旧 ZIP。

## 正式打包发布方法

发布到 Limix 门户时，不直接压缩本仓库。先在临时目录组成主套件源目录，只放需要进主包的工作流 skill；外挂源目录各自只放对应外挂。随后使用 Limix 的归一化脚本生成 ZIP：

```bash
python <limix>/private-deploy/scripts/publish_suite.py \
  --source <主套件源目录> \
  --output <输出目录>/product-workflow-skills-0.9.1.zip \
  --suite-id product-workflow \
  --package-id product-workflow-skills \
  --package-kind skill_bundle \
  --version 0.9.1 \
  --recommended-client codex
```

附件套件用同一脚本分别生成。`unit-test` 源目录只含 `unit-test-init`、`unit-test-generator`；`git-hook` 源目录只含 `git-hook-init`；`stitch` 源目录只含 `stitch-prototype`；`wiki` 只含wiki源目录。安全扫描不由本仓构建或发布，不要求相邻客户插件仓；项目若要另发，用该项目自己的源目录。外挂 `suite_id` 与 zip 名都不带 `product-` 前缀。


## ZIP 内必须包含的配置文件

归一化脚本会自动生成 ZIP，不需要手工编辑清单。最终每个上传 ZIP 的根目录必须是这样：

```text
suite-package.json
skills/
  <skill-id>/
    SKILL.md
    ...
```

`suite-package.json` 是门户读取的配置文件，关键字段包括：

- `schema_version`: 当前固定为 `1`。
- `suite_id`: 套件 ID，必须与门户目录 `itemId` 一致。
- `package_id`: 上传包 ID，例如 `product-workflow-skills`。
- `package_kind`: Skill 套件固定为 `skill_bundle`。
- `version`: 本次上传版本。外挂必须与对应 `SKILL.md` 的 `metadata.version` 相同，不从主套件 `VERSION` 自动取号。
- `recommended_clients`: 建议客户端，例如 `codex`，附件可带 `claude`、`cursor`。
- `contents.skills`: ZIP 内每个 Skill 的 `id`、包内路径、文件数、大小和内容 SHA256。

附件示例命令：

```bash
python <limix>/private-deploy/scripts/publish_suite.py \
  --source <单元测试源目录> \
  --output <输出目录>/unit-test-skills-0.8.1.zip \
  --suite-id unit-test \
  --package-id unit-test-skills \
  --package-kind skill_bundle \
  --version 0.8.1 \
  --recommended-client codex \
  --recommended-client claude \
  --recommended-client cursor
```

`git-hook`、`stitch`、`wiki`、`security-scan` 使用同样参数，只替换源目录、输出文件名、`suite_id`、`package_id` 和版本。

## 上传前检查

1. ZIP 根目录只有一个 `suite-package.json`。
2. 每个 `skills/<skill-id>/` 都有 `SKILL.md`。
3. 主包不含 `wiki`、`unit-test-*`、`git-hook-init`、`stitch-prototype`、`secidea-scan-gate`。
4. `suite-package.json` 的 `suite_id` 与门户目录 `itemId` 完全一致。外挂版本与所有同包 Skill 的 `metadata.version` 一致；先跑 `node --test tests/addon-versions.test.mjs`。
5. 同目录保留同名 `.sha256`，并用 `shasum -a 256 -c` 校验。
6. 不要用 Windows `Compress-Archive` 产物直接上传；跨平台统一跑归一化脚本。
