## 和 0.9.0 比，现场会碰到的变化

| 你会碰到 | 这一版怎么用 |
|---|---|
| 任务进度写哪里？ | 写 `.limix/projects/<项目短号>/<规格短号>/progress.json`。`implement` 是唯一上报节；`plan`、`kickoff` 只从工作流状态只读投影 |
| 怎么上报？ | 从 `implement` 提取临时扁平报告，顶层只含 `reportId`、`tasks`、`commits`，再走 `limix spec progress --from-file`。不把分节总文件直接交给命令 |
| 什么时候能报完成？ | 工作流完成再加合格 commit 才报 `done`。缺合格 commit 或证据不足时报 `blocked`，不回改工作流状态 |
| 收工前要核对什么？ | 目标任务为 `done`、已有合格 commit、有本轮验证证据、计划文件范围没有未提交改动。四项全过才按进度规则上报，再写 `slice_wrap_up`；缺一项就停 |

## 0.9.0 已经换过、这一版继续用的

| 你会碰到 | 这一版怎么用 |
|---|---|
| 线上规格怎么同步？`spec download` 还在吗？ | 0.9.0 起本地同步改走 `limix spec get/status/update`，开工硬卡过了再整套提交。本机没有这些子命令就是 CLI 没到位，先换 CLI（≥ 0.9.0），不要自己调接口 |
| 安全扫描 / 工具检查的结果往门户报，怎么分？ | 分两路。工具由 CLI 真实执行、由 CLI 合成上报的，才是「Harness CLI 单项报告」；用户或外部工具给的原始报告，只能按「外部结果参考」如实汇总，带上「未由 CLI 校验目标快照/时效，不是 Harness CLI 单项报告，不代表平台背书或工作流门禁」 |
| 门户上的检查为什么显示「过期」？ | Git 仓按 commit 判：报告里的 commit 等于当前 HEAD 就算「已检查」；HEAD 变了旧报告过期，过期说明保留旧 commit 与检查时间，旧结论不沿用。不带 digest 不判失败，CLI 在证据里标「内容未校验」 |
| 我的工作区不是 git 仓库怎么办？ | 走外部结果参考呈现，并把「纳入 git 后重跑」的指引写给用户；不要手工补快照换 pass |
| CLI 能上传单项报告 JSON 了吗？ | 不要手工构造单项报告 JSON 交给 `project sync`。CLI 没有公开的取摘要 / 报告摄入入口时，不复刻私有算法、不自造哈希补字段 |
| Setup 问什么？ | 按能力检查：本机 CLI 有没有需要的子命令、门户连不连得上；并区分 CLI 更新与 Suite 更新，缺哪项提示升哪项 |
| 门户基址写哪个？ | Setup 第一问推荐由项目确认的完整 HTTPS origin，你点头或改口之后才写入。也可以改成测试站、正式站，或其他私有化地址 |
| 外挂怎么装？ | code-wiki、安全扫描、单测、Git Hook、stitch、repo-wiki 仍单独装；用 skill 名互找，不写同仓相对路径 |

## 0.8.0 / 0.8.1 已经换过、这一版继续用的

制品键 `architecture` / `api`；任务态六态；确认开工；完整档可按尺子跳过；切片收工 `slice_wrap_up`；外挂目录和门户 `suite_id` 都不带 `product-`。命令面在 0.8 系列基础上增补 `spec get/status/update`。

## 不变的部分

- 阶段 skill 名称与顺序、源头磁盘文件名。
- 本地 `Draft` / `Reviewed` 状态机与看板生成器。
- `portal_sync=off` 整段不调 `limix`、不写门户状态文件。
- 主套件包不含外挂（0.7.1 起的口径）。Skill 不调 kickoff / complete API。
- 建议不挡编码：单测 / Git Hook 是建议项，必填仍是已批 PRD + 开发计划。

## 这一版做了

### 0.9.0：产品与工作流 Skill

- `$product:setup` 按能力检查 CLI 与门户，并区分 CLI 更新和 Suite 更新。
- `$product:kickoff` 改为开工硬卡通过后做规格三方核对，再整套提交；同步命令改为 `limix spec get/status/update`。
- `$product:workflow`、`$product:review` 与公共契约同步采用新的核对、提交和冲突停下规则。
- Harness 结果分两路：CLI 真实生成的是单项报告；外部工具或用户提供的是外部结果参考。Git 仓按 commit 判断新鲜度。
- code-wiki 接入产品工作流上下文；安全扫描、单测、Git Hook、stitch、repo-wiki 仍是独立外挂，版本维持 0.8.1。

### 0.9.1：实现进度与收工

- `$product:develop` 把实现进度写入分节 `progress.json`；只从 `implement` 提取临时扁平报告上报。
- 工作流完成且有合格 commit 才报 `done`；缺 commit 或证据时报 `blocked`，不回改工作流状态。
- `$product:wrap-up` 收工前核对任务状态、合格 commit、本轮验证证据和未提交改动；四项全过才写 `slice_wrap_up`。
- 评测：progress-sync 复跑 5/5；wrap-up 8/8；投影专项复跑 4/4。0.9.0 历史轮次独立保留。

### 0.9.2：收尾来源检查 + 六项最小增强（01–06，规则与行为评测均已完成）

规则已落地，确定性检查全绿；每票配了正/反/边界行为场景，共 20 条，入各 bundle `evals/evals.json`。模型行为评测 2026-10-10 至 10-13 跑完，结果见下表。另含收尾来源检查（`collect-wrap-up-sources.py`）：来源检查分全缺 / 单侧 / 部分已有三分支，缺材料时正确暂停并只索取缺失侧，不把未确认的验证写成通过。

- 01 有效输入与缺失信息处理：公共契约新增节，澄清/PRD/章程规则引用；记录在现有产物不另造输入清单，缺必要业务图不确认相关范围，缺装饰参考不阻断，旧 PRD 污染复核受影响内容。
- 02 续跑与无效循环处置：公共契约新增节，`$product:workflow`、`$product:develop` 引用；复用 state、计划与证据接下一项，已批准阶段不重做，冲突报告差异不改绿，重复失败无新信息时给恢复选项，合法长任务不设耗时阈值。
- 03 共享合同事实源与变更影响：公共契约新增节，技术方案与计划引用；复用既有事实源，变更前列调用方、兼容性与验证范围，缺事实列待确认，不另造第二份合同或自定 fixture 目录。
- 04 终验对照：`product-workflow-suite/product-wrap-up/references/verification-report-template.md` 增「关键控件/字段对照」，wrap-up 清单引用；批准依据与实现证据成对，差异改实现对齐或人批准修订，未处理不写通过，不新增重复报告。
- 05 依赖升级边界：`product-workflow-suite/product-workflow/references/add-not-upgrade.md` 扩两条路径（现版本继续 / 明确升级任务），暂缓记 `not-run` 不写通过，不为变绿移除门禁；`product-develop` 引用。
- 06 技术字符串原样保留：公共契约「语言和产物」新增两行，技术串写进行内代码或代码块、不夹 Markdown 转义，正文 Markdown 不受约束；`product-develop` 引用。
