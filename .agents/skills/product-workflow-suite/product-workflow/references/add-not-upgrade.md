# 门禁只增加

写测试脚本或构建命令前，先读现有架构：语言、运行时、包管理器、测试框架、依赖版本。

完成标准：脚本能在**当前**工具链上跑通一条冒烟。沿用仓库里已有的版本号。

配置变更优先零侵入：能靠命令行参数 / 临时 init script / `--no-save` 拿到的报表，不改构建文件；必须写构建文件时，先出 diff 请用户批准。

用户豁免并记下责任人后可以先写业务代码。豁免记录是编码完成条，不是测试已通过。

旧 API 报错、废弃警告或编译错误不自动授权升级依赖，也不自动授权改门禁。两条路都能走，按用户的决定选：

- **现版本继续**：改调用、参数或配置，先在当前工具链跑通一条冒烟；依赖版本保持不动。
- **明确升级任务**：把升级范围、受影响依赖、回归验证和批准人写进计划，获批后再执行；未批准不升级。

暂缓或装不上依赖的检查，记 `not-run`/暂缓与原因，不写成通过；不为变绿移除、跳过或放宽现有正确门禁。
