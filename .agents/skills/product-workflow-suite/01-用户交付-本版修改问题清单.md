# haitian-pw-0.9.1 修改问题清单（给安装同事）

发布：2026-09-30

装这一版后按表核对。现场还碰到已经改过的问题，反馈版本名 haitian-pw-0.9.1 和步骤。

## 装之前先做一件事

确认本机 `limix --version` **≥ 0.9.0**，且 `limix spec --help` 里有 `get`、`status`、`update`。缺子命令先换 CLI，再开工同步。CLI 0.9.0 未发布前这一版先不进现场，仍用 0.8.1。

## 和 0.9.0 比改了什么

| 问题 | 这一版 |
|---|---|
| 任务进度写在哪里、怎么上报 | 写 `progress.json` 分节总文件；只把 `implement` 的临时扁平报告交给 `spec progress --from-file` |
| 没有合格 commit 能否报完成 | 不能。工作流完成但缺合格 commit 或证据时上报 `blocked`，不回改工作流状态 |
| 收工前还要查什么 | 查任务 `done`、合格 commit、本轮验证证据、计划范围无未提交改动。四项全过才上报并写 `slice_wrap_up` |

## 0.9.0 已改、这一版继续用

1. 门户同步改走规格三方核对与整套提交：`limix spec get/status/update`。开工硬卡过了才提交。写成 Draft / Reviewed 不会自动传。
2. 检查结果分两路报：CLI 真实执行合成上报的才是「Harness CLI 单项报告」；外部工具给的原始报告按「外部结果参考」如实汇总，带三句限制语（未由 CLI 校验快照/时效、不是 CLI 单项报告、不代表平台背书或门禁），不冒充、不上传单项报告 JSON。
3. 新鲜度按 git commit 三档判：报告 commit == 当前 HEAD 即「已检查」；HEAD 变了旧报告过期，过期说明保留旧 commit 与检查时间；非 git 工作区走外部参考并提示纳入 git。缺 digest 不判失败，标「内容未校验」。
4. Setup 按能力检查：CLI 缺子命令、门户连不上会分别提示，并区分 CLI 更新与 Suite 更新。
5. code-wiki、安全扫描、单测、Git Hook、stitch、repo-wiki 仍单独装；用 skill 名互找，不写同仓相对路径。

## 接着用的（0.8.x 已改）

制品键 `architecture` / `api`、任务态六态、确认开工、完整档可按尺子跳过、切片收工 `slice_wrap_up`、外挂目录去掉 `product-` 前缀。

## 这一版不做

- CLI 侧公开取摘要 / 单项报告摄入命令（平台侧跟踪）。
- GitLab CI 强制安全门禁。
- 加密需求、飞书读图（#27）。
- 提交钩子把开工/收工钉进 git。
- 门户遗留项（`upload --force` HTTP 500、test 站安装短链、安装资产上架）——门户侧跟踪。
