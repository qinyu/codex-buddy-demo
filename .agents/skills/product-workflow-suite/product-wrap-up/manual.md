# 验收收尾与知识回写 ($product:wrap-up)

`product-workflow-0.9.3`

当代码改完、单元测试也跑过了，如何确保交付的成果没有隐患、如何保证长期的架构文档没有过时？`$product:wrap-up` 是整个产品工作流的**交付检查点与知识闭环枢纽**。

它的核心原则是：**“无新鲜验证证据，不得宣称门禁已通过；代码若有架构演进，必须回写知识库。”**

---

## 一、什么时候触发本技能

收尾检查是一个严格的把关环节，在以下任一时刻触发：

1. **切片实现完成，准备确认收工之前**；
2. **向用户汇报“已开发完成 / 缺陷已修复”之前**；
3. **准备切换到下一个需求切片之前**。

即使你在聊天框里没有明确提到“收尾”或“wrap-up”，工作流在结束编码后也会自动触发本技能进行全面核验。

---

## 二、收尾清单：它会严格核验什么？

助手会严格运行收尾检查清单（Checklist），只有全部通过才允许宣布切片完成：

### 1. 状态一致性检查
- 校验 `.workflow-state.json` 状态机文件的合法性。
- 核对所有依赖的阶段产物是否真正获得了人工批准（`Reviewed`），杜绝 AI 自作主张推进。
- 如果走的是轻量工作流（`lite`），必须通过 `validate_lite_slice.mjs` 的强硬校验。

### 2. 证据真实性检验 (Gate Function)
- **拒绝历史记忆与口头保证**：绝不允许说“我之前跑过测试是绿的”。必须是当前代码新鲜运行生成的终端回显与真实退出码（`Exit Code: 0`）。
- **字段成对核对**：检查代码中实际实现的字段、API 接口和数据库列，是否与批准的需求文档成对匹配，严禁私自缩水或塞入未经批准的私货。

---

## 三、知识库检查与局部增量回写

很多团队的系统知识库（Wiki）之所以沦为僵尸文档，是因为“需求上线了，架构文档却没人改”。`$product:wrap-up` 从机制上保证了系统知识库与实际代码同步演进。

> 💡 **底层运行机制：自动调用 `$wiki` 进行增量回写**
> 1. **Wiki 约定逐条对照**：收尾时，助手会从已有的 `Project Wiki` 中提取本切片涉及的约定（例如组件复用规范、跨模块接口、防重复造轮子原则），逐条核对代码是否违背。如果有偏离，要么改代码纠正，要么向你汇报并请求更新知识。
> 2. **自动触发增量更新**：如果本次需求引入了新的服务、公共模块、枚举值或数据模型变化，Wrap-up 会**自动通过 Skill 调用 `$wiki`（传递 `task=update`）**！
> 3. **只更新有真实证据的事实**：它只把本次切片中已经实现、通过测试验证的增量事实回写进 `docs/wiki/`，不凭空推测未来的计划，绝不重跑繁琐的 `$product:setup`，真正做到**代码改到哪，系统知识库就自动同步到哪**！
> 
> ```mermaid
> flowchart TD
>     FinishDev["编码完成 / 提交验证前夕"] --> Trigger["触发 $product:wrap-up"]
>     Trigger --> GateCheck{"Gate Function 严格核验<br/>(fresh evidence)"}
> 
>     GateCheck -->|"检查 Exit Code 与日志"| PassTest["必须新鲜终端回显且 Exit 0"]
>     PassTest --> FieldMatch["代码实现字段与 PRD 成对核对"]
>     FieldMatch --> WikiCheck{"架构演进检查<br/>(是否涉新服务/数据模型/接口)"}
> 
>     WikiCheck -- "有架构或模型新增" --> WikiUpdate["自动内部调用 $wiki(task=update)<br/>增量回写 docs/wiki/"]
>     WikiCheck -- "无架构变更" --> GenReport["生成收尾报告 verification.md"]
> 
>     WikiUpdate --> GenReport
>     GenReport --> HumanApproval{{"最终人工批准收工"}}
>     HumanApproval --> MarkDone["状态机正式标记切片完成<br/>(.workflow-state.json)"]
> ```

## 四、关键产物全貌

收尾完成后，会在切片目录下产生并锁定以下交付依据：

| 产物文件 | 存放位置 | 核心作用与内容 |
|---|---|---|
| `verification.md` | `wrap-up/<切片名称>/` | **收尾验证报告**。完整记录本轮执行的验证命令、真实退出码、受影响字段对照表以及遗留风险清单。 |
| `.workflow-state.json` | 切片根目录 | **最终状态标记**。适用门禁全部通过后，由脚本写入 `slice_wrap_up` 记录，正式标记切片完成。 |
| `docs/wiki/` 增量更新 | 仓库根目录 | **持久知识回写**。同步本次变更的架构图谱、数据模型与术语定义。 |

> ⚠️ **关键红线：切片收工硬核验**
> 只有当测试通过、本地提交干净（无未追踪与未提交脏代码）、Wiki 回写完毕，且经你人工核验批准后，切片才能真正收工。任何一项缺口都会导致收工被拦截，并如实向你报告未完成项。
