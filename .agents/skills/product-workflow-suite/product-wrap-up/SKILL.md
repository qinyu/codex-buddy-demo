# Product Wrap-Up（收尾检查）

> 套件成员。版本见根目录 `VERSION`。

## 定位

收尾 = 走完 product-workflow 既有契约（阶段批准门禁、输出契约、双视图契约、H5 图示契约）的**检查点**，不是新流程。检查不通过时，不得宣布完成、不得进入下一阶段、不得切换切片。

## 触发时机

以下任一时刻，先跑本 skill 再继续：

1. 请求用户评审当前阶段产物前
2. 宣布「完成 / 通过 / 已修复」前
3. 切换或插入切片前
4. 修改 / 修复后向用户汇报前

## 证据铁律

**无本轮新鲜验证证据，不得宣称测试/门禁已通过。** 字段对照先走下面的来源检查。用户豁免编码时：完成标准是责任人和风险已写入 `develop.md` 与 state，不是测试绿。

### 字段对照来源检查

先读已授权的变更范围、批准材料、源码或 DDL 与既有验证报告，再判断是否足够。只处理本轮受影响项；模板在记录对照或缺口时加载。

| 查得的材料 | 动作与完成条件 |
|---|---|
| 真实字段与两侧来源齐全 | 在既有验证报告中成对记录批准依据和实现位置，核对语义与差异；来源齐全只完成该对照，不替代其余收尾检查 |
| 字段和来源全缺 | 输出「尚未完成」、已查位置、最小缺失材料及继续条件；暂停相关对照和完成声明，用缺口说明代替占位字段行 |
| 真实字段已知、仅有一侧 | 保留真实字段和已知来源，将另一侧记为缺口；只索取缺失侧。缺口记录仍未完成 |
| 已有部分真实对照 | 与本轮来源核对并保留有效行，只补本轮范围内的缺口；旧结论须有本轮核对证据 |

能自行查到的材料先查，不要求用户重复提供。缺口只暂停受影响项，无关独立工作可以继续；汇报分别列已做、未做与继续条件。

### 证据与声明对应

每条验证声明按「声明 → 检查对象 → 本轮输出」对应：证据只支持它实际检查的对象，按声明选证据，不按命令名或 exit 0 推绿。

| 本轮动作 | 支持的声明 | 不支持的声明 |
|---|---|---|
| 清点 / 定位授权文件（find、ls、rg 等） | 已查位置、发现的来源或缺口 | 字段实现符合批准材料、实现验证通过 |
| 成对核对批准材料与实现 | 受影响字段的对照结论与差异 | 未运行的动态检查、全部收尾通过 |
| 执行与声明相关的测试 / 校验 | 输出与退出码支持的具体结果 | 未覆盖的字段或整套收尾通过 |
| 报告落盘后的回读 | 报告存在且记录一致 | 报告里的实现结论已验证 |

工具名不决定证据等级：`write` / `edit` 的 `then_run` 真跑校验时是验证证据；只回显一句话时不是。

Gate Function（每项「完成」声明必经五步）：

1. **IDENTIFY**：哪条命令 / 检查能证明这条声明？
2. **RUN**：本轮完整执行——「之前跑过」「应该能过」不算证据。
3. **READ**：读完整输出、退出码、失败数，不只看结论行。
4. **VERIFY**：输出是否支持声明？不支持 → 如实报告实际状态。
5. **ONLY THEN**：才允许宣告完成。

失败对照（禁止的情况）：

| 声明 | 需要 | 不足够 |
|---|---|---|
| 测试通过 | 本轮 test 输出 0 失败 | 之前跑过 / 应该能过 |
| 看板已同步 | md/state 已更新；打开壳能看到新内容 | 只口头说同步 |
| 文档已更新 | 受影响文档 diff 确认 | 「已同步」口头声明 |
| Bug 已修复 | 重跑原始症状通过 | 代码改了就算好了 |
| 阶段已批准 | 用户明确批准记录 | AI 自行推进 |

## 收尾清单

逐项执行，全部通过才可宣布完成。无法执行的项记 `skipped` / `not-run` 并附原因，**不得伪造结果**。

### A. 状态一致性

先留原始状态，再处理缺口。修复前先对原状态运行下述适用校验，保存完整输出和退出码；根据源头事实再修复，另存重验回执。不能先补 N/A 原因或其他缺项，再把修后的通过记录称为原状态初验。校验不可运行时如实记录，不造失败输出。

- [ ] `.workflow-state.json` 已过本机 `product-workflow` skill 目录下 `scripts/validate_workflow_state.mjs <工作流目录>`：无错误、无 BOM，`current_stage` 与各阶段 status 符合实际。`run_mode=lite` 时还必须通过同目录 `validate_lite_slice.mjs <工作流目录>`
- [ ] 核对本次所依赖批准的产物与来源。历史 `Reviewed` 缺出处时，先查已有记录；仍无法核对的，保留历史记录并明确请用户核对该阶段批准出处，将缺项及请求记入验证报告。未取得当前所需批准，不标作批准已通过；未批准阶段未标记 Reviewed。豁免项已写入 state 顶层 `waivers[]`，且看板显示「已豁免 · 未完成」（参照测试基建门禁规则）

- [ ] 未修改的已批准产物，保留其历史 `Reviewed` 与签署事实；另存新验证报告不自动降级旧对象，新输出在现有报告中独立标为待批。真正回改已批准产物时，才按公共契约原回改规则置 `Draft` 并标 `revising: true`，等待复审。

### B. 产物完整性

- [ ] 当前阶段产物存在且达标：full 有 J-/US-/AC-/TC-/TASK- 追踪；lite 有短 PRD 的 AC 与短开发计划的 TASK 对照。有上下文、无 TBD/占位（见输出契约）
- [ ] 源头已更新（阶段 `*.md` + `.workflow-state.json`）；未为同步展示去改或提交看板 HTML。本轮改过源头的，已从 `product-workflow` skill 目录运行 `scripts/render_review_board.mjs`，`.review-board/index.html` 存在。工作流目录 `.gitignore` 已排除 `.review-board/`。
- [ ] PRD / 开发计划请求人批前，源头已有 `## 对抗审查`；有阻断发现时未请人按已通过批准
- [ ] 本轮已按公共契约 § 制品账与门户同步处理：`off` 时未调 `limix`、未写门户状态文件；`bound_project` 只调用 `portalHandoff` 并记下未同步
- [ ] 进入实现前已按公共契约 § 开工前交付物核对
- [ ] 产物位于标准目录 `docs/product-development/YYYY-MM-DD-<主题>/`

### C. 文档回写与对照

- [ ] 受影响文档（prd / prototype / test-cases / technical-solution / development-plan）已同步本次变更
- [ ] 实现对照已批 PRD / 原型 / Wiki；字段和组件能在源码或 DDL 里找到（先读再写：现有源码、注释与文档、表结构、已批 PRD / 原型 / Wiki）。受影响的关键控件/字段已写入验证报告 `references/verification-report-template.md` 的「关键控件/字段对照」：批准依据与实现证据成对，差异要么改实现对齐、要么人批准修订，未处理不写通过；只列受影响项，不新增重复报告
- [ ] **Wiki 约定逐条对照**（问题 #37）：从 Project Wiki / PRD / 原型提取本切片约定条款（组件复用、边界、接口、禁造字段），逐条给出「代码位置」或「未做 + 原因」；静默偏离不得宣称完成。偏离处理只有两种：改代码对齐，或回写 wiki 并经用户批准。逐条对照表写入验证报告。
- [ ] 长期知识确有变化时，通过Skill调用 `wiki`，传 `task=update`、`workspace`、`targets`、`read_scope.docs/source`、`write_scope`、`graph_ops`、`authorization_confirmed`及各项用户授权依据。targets列要改的页面，read_scope分别列已获准文档与实现证据，write_scope只列获准写入范围；图query/build/sync独立列仓库。工作区位置不授予全仓阅读许可；缺项传unknown，不为补交接先读邻页。只更新已实现且有证据的事实；无变化不写，计划不冒充现状，偏离批准约定先决策。缺Wiki或材料时记录未完成项，不伪装更新、不重跑Setup。可选执行器模式仅由用户明确选定才启用，未选定保持自然语言路径。
- [ ] 涉及切片时，切片总览表 `slices-overview.md` 已更新

### D. 证据与汇报

本轮执行事实优先另存 `wrap-up/<阶段或切片>/verification.md`，不为登记新执行而改写已批准的 `develop.md`。未改正文时沿用 A 条保留历史签署，新报告独立待批。若确需追加或改动已批准正文，这仍是回改，须依 A 条置 `Draft`、`revising: true`；仅在正文写“本轮待批”不能代替状态回改。

- [ ] 每次验证命令已本轮执行（含编辑 / 写入后的自动运行），命令、cwd、完整输出和真实退出码留档（存 `wrap-up/` 或产物目录）；失败与重跑分开留档，回读后按实际回执填写报告
- [ ] 验证报告已落盘 `wrap-up/<阶段或切片>/verification.md`（模板见同目录 `references/verification-report-template.md`）；报告中的执行事实逐项对照实际回执及运行前记录 / 文件（包括环境、退出码、已有产物及变更），缺少实测依据的记「未查」，不从模板或旧文件存在推定本轮结果
- [ ] 逐条验证声明均有本轮对应检查与留档输出（存 `wrap-up/` 或产物目录）；清点 / 回读只记实际动作，缺实现材料时实现验证记 `not-run`，不因清点成功或本项其他内容通过而标绿
- [ ] 收尾汇报包含四要素：文件变更 / 依据编号 / 验证命令与结果 / 遗留风险

### E. 切片收工

仅当本轮是**本切片实现收尾**（宣称切片做完、切下一切片、确认收工）时执行。请求阶段评审、修完一点再汇报：跳过本条。

先按 `.workflow-state.json` 的 `run_mode` 核对适用批准门：沿用本清单 A 条的本机已安装 `product-workflow` 目录定位，只读其公开 `references/run-mode.md` 对应门禁，不调用人专用 `$product:workflow`、不运行连跑。`lite` 按「lite 文件与两道门禁」核对短 PRD 批准及本次 `develop.md` 验证证据的人批来源，批准对象须与本轮证据匹配。参考缺失、安装不完整或无法确定适用模式时，如实报告无法核对，不推定批准门通过。

**收工核对**——适用批准门通过后，用本机已安装 `product-workflow` 的 `scripts/validate_lite_slice.mjs` 导出的 `checkLocalCloseout` 做以下四项。它只返回缺项和待写入内容，不改 state。适用批准门和四项通过时，由同一脚本的 `writeLocalWrapUp` 写入 `slice_wrap_up`，与门户绑定及同步结果无关。失败不写。**批准门或四项核对任一缺失就停：不写 `slice_wrap_up`、不上报 `done`，把缺项如实报给用户**：

- [ ] 目标任务在 `.workflow-state.json` 的 `tasks[]` 中显式为 `done`；提交数、阶段 Reviewed 或测试通过都不推导任务完成
- [ ] 目标任务已有合格 commit：已批准开发计划中的 TASK 文件范围已提交，且提交说明指向该 TASK；`slice_plan.files` 只作历史观察，不是范围权威；chore、无关提交不算
- [ ] 已有本轮验证证据：`wrap-up/<阶段或切片>/verification.md`（或本清单 D 条留档）由本轮跑出，内容支持完成声明。复用已有测试时，报告写明覆盖依据和本轮执行，缺一不能收工
- [ ] 计划文件范围没有未提交改动：`git status` 对已批准开发计划列出的 TASK 文件范围为空

本地记录写入后，本地收工完成。`bound_project` 的同步作为独立后续交接，按公共契约的门户接入指针处理；缺接入能力或同步失败只报告未同步，保留本地完成记录。`off` 零门户调用和状态写入。

切片收工完成：适用批准门与四项收工核对全过，且 state 里有本轮 `slice_wrap_up`。门户规格是否已完成，看网上状态。

## 失败处理

收尾不通过时按序处理，**不降级通过**：

1. **诊断**：定位是状态 / 产物 / 文档哪一类问题
2. **处置**：批准或批准出处缺口，列明所需用户核对 / 批准及证据，等待用户；可修的产物缺口（重建看板 / 补产物 / 同步文档 / 补验证）针对根因修复后重验，并继续核对其他门
3. **重验**：重新跑收尾清单，最多迭代 3 轮
4. **仍不过**：如实向用户报告阻塞项与原因，等待用户处置

## 汇报格式

按验证报告模板输出。完整收尾清单全部通过且有本轮新鲜证据时，才用下面的成功句式；三个字段对照齐全不等于收尾全部通过。用户只关心结论时，用四要素一句话：

```text
完成。<阶段/切片> 收尾通过：改 <文件>（依据 <编号>），验证 <命令> <结果>，遗留 <风险>。
```

材料不足时使用未完成句式，按实际动作填写，不把计划当结果：

```text
尚未完成。已查 <位置>、已做 <实际动作>；缺 <最小来源>，相关对照暂停。取得 <继续条件> 后补核；其他未运行检查仍未完成。
```

## 与既有契约的关系

- 本 skill 引用但不重复 product-workflow 的阶段批准门禁、输出契约、双视图契约、H5 图示契约；
- 本 skill 是 AGENTS.md「文档回写义务」的强制检查点，切片切换须过本检查（见 AGENTS.md 执行纪律）。
