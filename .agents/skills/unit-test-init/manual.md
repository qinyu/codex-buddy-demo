# 单元测试环境初始化 ($unit-test-init)

`product-workflow-0.9.3`

当接手一个缺少测试环境的老代码仓，或者新工程尚未配置测试框架时，本技能用于识别技术栈并生成原生的测试环境初始化脚本与测试报告适配配置。

---

## 一、解决什么问题

在没有成熟单测基建的代码库中：
- 缺乏可执行的测试命令，开发计划无法绑定可验证命令，导致工作流验证受阻；
- 缺乏标准化的报告输出，下游工具无法自动收集测试结果或覆盖率；
- 不同操作系统（Linux、macOS、Windows）下的依赖安装命令各异，人工排查依赖容易出错。

`$unit-test-init` 快速识别项目语言与构建工具，生成适配当前系统的原生测试初始化脚本，搭建起最小可用的单测运行骨架。

> 💡 **底层标准与报告采集机制**
> 
> 为了保证测试结果既能被开发者在本地直观查看，又能被 CI/CD 或下游工作流门禁准确解析，本技能生成两个标准格式的报告适配：
> 1. **测试执行结果**：统一生成标准 JUnit XML 格式（`junit.xml` 或 `TEST-*.xml`），记录用例通过率与断言失败详情；
> 2. **代码覆盖率报告**：统一生成 Cobertura XML 格式（`reports/coverage.xml`），供质量报告度量各模块行覆盖率。
> 
> ```mermaid
> flowchart TD
>     Detect["1. 识别工程语言与构建工具<br/>(Maven/Gradle/npm/Go/Pytest)"] --> GenScript["2. 生成原生初始化脚本<br/>(init_test_env.sh 或 .ps1)"]
>     GenScript --> HumanRun["3. 开发者在终端手动执行安装"]
>     HumanRun --> OutCheck["4. 输出标准化报告文件<br/>(junit.xml & coverage.xml)"]
> ```

---

## 二、怎么对助手开口

直接提出单测环境搭建诉求：

```text
当前仓库还没有单元测试环境，帮我初始化一套基于 Jest 的单测运行基建。
```

或者使用技能指令：

```text
$unit-test-init
```

---

## 三、运作逻辑与安全约定

1. **识别技术栈，生成原生脚本**：
   - Linux / macOS / WSL：生成 `init_test_env.sh`；
   - Windows 原生环境：生成 `init_test_env.ps1`。
2. **人类保持最终控制**：
   生成的初始化脚本**由开发者在终端手动运行**，助手不擅自执行全局依赖安装。若需要修改构建配置文件（如 `pom.xml` 或 `package.json`），先给出修改对比（diff），经你批准后才写入。
3. **后续协作**：
   环境就绪后，若需为特定业务文件生成单测用例，可配合 [单元测试生成与维护](unit-test-generator.html) 使用。
