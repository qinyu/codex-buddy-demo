# 额度重置倒计时格式化函数（轻量 PRD）

本 PRD 用于决定是否批准一个局限于 StickS3 固件显示逻辑的小改动。评审人需确认显示规则、变更边界和验证方式；批准本 PRD 后，才进入开发计划与实现。项目是从 1 到 N 的既有产品迭代（来源：`.product-workflow-config.json` 的 `workflow_policy.product_mode=one_to_n`）。

## 范围

- 当前固件在 `src/main.cpp` 的 `resetText` 与 `resetTimeText` 中分别格式化重置倒计时，覆盖按天、按小时、按分钟及已到点等路径。
- 本次为额度重置剩余时长提供一个可复用格式化函数，明确处理超过一天、超过一小时、不到一小时、到点、负值，以及无倒计时或时间不可用/无效；需要时由现有显示入口调用。
- 允许修改范围：`src/main.cpp` 及本切片要求的针对性测试文件（如实现需要）。不改 BLE 数据协议、数据源、设备布局或其他平台。
- 小于一小时的正剩余时间须给出非零且直观的分钟显示（例如不足一分钟显示 `1m`），避免仍未到点却显示 `0m`；到点或负剩余时间统一显示明确的已到点文案。显示沿用当前固件英文文案风格。

## 验收

- **AC-001**：倒计时大于一天时，格式化结果清楚显示天数及剩余小时，且超过 24 小时的值不会只显示小时。
- **AC-002**：倒计时大于一小时且不足一天时，结果清楚显示小时及剩余分钟。
- **AC-003**：倒计时大于零且不超过一小时（包括不足一分钟）时，结果清楚显示剩余分钟，不出现误导性的 `0m`。
- **AC-004**：剩余时间为零或负数时，结果显示明确的已到点状态，不显示负的天/时/分数，也不把过去时间显示成仍在倒数。
- **AC-005**：没有倒计时值，或当前时间不可用、输入时间值无效而无法计算正常倒计时时，结果统一显示 `NA`（Not Available）；不得显示为空字符串、`resets --`、已到点文案或伪造的倒计时。

## 验证

- 目标仓库：当前 codex-demo 固件仓库；项目已有 Python `unittest` 入口 `python3 -m unittest discover -s tools -p 'test_*.py'`，以及 StickS3 构建入口 `pio run -e m5stack-sticks3`。这些是仓库文档记录的验证入口，尚未在本 PRD 阶段执行。
- 实现后应对格式函数的边界值进行针对性自动化验证；同时运行 Python 测试发现命令和 StickS3 固件构建。若格式函数留在 Arduino 固件编译单元、无法由现有 Python 测试直接调用，应在计划中明确测试接缝或采用的可行替代验证，不得以仅有构建代替边界行为检查。
- 通过标准：AC-001 至 AC-005 对应边界均有可复核结果，现有测试与 StickS3 构建通过；未执行项如实记录。

## 不做

- 不改变倒计时的数据来源、UTC 取时、颜色策略、更新频率、布局和数据协议；`NA` 仅是无可用倒计时文本的显示规则。
- 不重构整个仪表盘或修改其他设备环境、桥接程序、插件及服务端。
- 不扩展为本期自动化测试计划或完整测试用例阶段；本项仅要求格式函数边界行为的直接验证。

## 约束、风险与待确认

- 已确认事实：配置要求自动化测试和单元测试基建检查；源码中存在 `resetText`、`resetTimeText` 两个格式化入口，时间来源由 `dataUtcNow` 提供。依据：`.product-workflow-config.json`、`src/main.cpp:1104`、`src/main.cpp:1129`、`AGENTS.md`。
- 轻量模式是用户本轮明确选择。针对 `workflow_policy.test_automation=required` 的覆盖记录：本需求只涉及一个固件模块中的纯格式化规则，不单独产出自动化测试计划；风险是没有独立计划来约束跨环境自动化覆盖；回收点是在实现时补足边界行为的自动化验证，并按本切片验证记录确认其可执行性。
- 时间阈值以剩余秒数判定；等于一小时归入“不超过一小时”，等于一天归入“按天显示”。若需求方对阈值边界有不同定义，需在批准前指出。
- 异常时间定义：无倒计时值、无法取得当前 UTC 时间，或输入时间无效到无法计算剩余时间，统一属于不可用；过去的有效重置时间仍按 AC-004 显示已到点，不归类为无效。
- 用户确认：2026-10-28，用户明确同意不足一分钟按向上取整显示分钟数（例如 1 秒显示 `1m`）。该规则纳入 AC-003，作为已确认规则而非待确认假设。
- 未决项：无已知阻断项。
